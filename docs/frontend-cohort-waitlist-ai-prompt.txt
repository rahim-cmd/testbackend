2) JOIN THE WAITLIST (Public)
-------------------------------------------------------------------
Endpoint
- POST /waitlist
Headers
- Content-Type: application/json
Body
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "phone": "+1 555 123 4567",
  "message": "Would love to join the next cohort."

Notes
- name (required, 2-150 chars)
- email (required, valid email)
- phone (optional, up to 30 chars)
- message (optional, up to 1000 chars)
- cohort_id (optional) — omit it; the backend automatically attaches the signup to the current open cohort.

Success Response (201)
{
  "success": true,
  "message": "You have been added to the waitlist successfully.",
  "data": { "id": 8, "cohort_id": 1 }
}

Error Response (422) — validation errors
{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "field": "email", "message": "A valid email is required." } ]
}

- On 422, map `errors[].field` to the corresponding input and show inline messages.

ADMIN NOTE (for reference, if there is an admin dashboard section for this)
-------------------------------------------------------------------
Admin-only endpoints (require Authorization: Bearer <admin_token>) to manage the cohort offer and waitlist, in case an admin UI section is needed:
- POST /admin — create a cohort (body: title, description, price, currency, duration_weeks, session_duration_minutes, max_members, start_date, session_day, session_time, workbook_url, features: string[], status).
- GET /admin — list all cohorts.
- GET /admin/:id — get one cohort.
- PUT /admin/:id — update any field above, including `seats_taken` and `status` (draft/open/full/closed) to manually track enrollment since there is no online payment yet.
- DELETE /admin/:id — delete a cohort.
- GET /admin/waitlist?status=&cohort_id= — list waitlist signups (status: pending/contacted/converted/cancelled).
- PUT /admin/waitlist/:id/status — body: { "status": "contacted" | "converted" | "cancelled" | "pending", "admin_note": "optional note" }. Marking an entry "converted" only updates the waitlist entry — to actually seat them, use the allotment endpoint below.

Member allotment (this is how admin manually enrolls someone — from the waitlist or directly by user id/email — since there is no online payment):
- POST /admin/:id/members — body: `{ "user_id": 5 }` OR `{ "email": "person@example.com" }`, optionally with `{ "waitlist_entry_id": 8 }` to also mark that waitlist entry as converted. This is how "priority for waitlisted users" is applied in practice: when a cohort fills up, new signups go to the waitlist; when the next cohort is created ~7 weeks later, the admin works down the waitlist list (oldest first) and calls this endpoint for each person to seat them into the new cohort before opening it up publicly.
- GET /admin/:id/members — list all members of a cohort with join status.
- PUT /admin/members/:memberId/status — body: `{ "status": "active" | "completed" | "cancelled" }`. Cancelling frees up a seat automatically.
- PUT /admin/members/:memberId/join-control — body: `{ "is_enabled": true|false, "reason": "optional" }`. Use this to block/allow a specific member's Zoom join access across all sessions (e.g. payment not yet received).
- GET /admin/members/:memberId/join-logs — audit trail of when the member opened/closed a session from their dashboard.

Session management (the 7 weekly Zoom meetings for a cohort):
- POST /admin/:id/sessions — body: `{ "sessions": [ { "week_number": 1, "theme": "Foundations", "session_date": "2026-11-02", "start_time": "18:00", "end_time": "19:30" }, ... ] }` for all 7 weeks. If a session's `zoom_link` is omitted, the backend automatically creates a real Zoom meeting for it; you can also pass an explicit `zoom_link` to skip auto-creation.
- GET /admin/:id/sessions — list all sessions for a cohort.
- PUT /admin/sessions/:sessionId — update theme/date/time (also re-syncs the Zoom meeting automatically if one exists).
- POST /admin/sessions/:sessionId/members/:memberId/send-link — body: `{ "admin_note": "optional" }`. Explicitly emails that one member their Zoom link directly. This is the ONLY path that ever sends a Zoom link by email — use it sparingly, e.g. if a member says they can't find it on their dashboard.
